Heat diffusion,
in parallel

We simulate a cooling plate and compare two ways to solve the same temperature equations: Jacobi and conjugate gradient (CG).

Research question

How much faster do more processes make the solve, and when does MPI communication become the main cost?

Srikar Palani and Suprathik Vinayakula
CS598 Midterm Project · Fall 2026

The study compares time to the same residual tolerance, across 1–64 MPI processes and 280 measured runs.

✛CS598 / MPI heat diffusionModel

Each time step requires a linear solve

Physical model: a unit-square plate, warm regions inside, and edges held at zero temperature.

The temperature model

An N × N grid represents the interior. Heat moves between neighbors; larger N gives a finer grid. Backward Euler advances one physical step by solving:

A x = b

b is the current temperature field.
x is the next temperature field.
A describes the neighbor interactions.

Each point interacts with four neighbors. The code calculates these five-point interactions directly instead of storing a huge matrix.

A physical time step advances the simulation. Solver iterations are the repeated updates needed to solve A x = b within that step.

✛CS598 / MPI heat diffusionParallel method

MPI processes share the plate

P is the number of MPI processes. A process is also called a rank; each rank owns one grid block.

Two communication patterns

Neighbors exchange halos

A rank needs values just beyond its block to update points along the edge.

All ranks combine scalars

Global reductions combine local results for dot products and convergence checks. These calls can include waiting for other ranks.

More ranks reduce the cells owned by each process, but halo exchanges and global reductions remain necessary.

✛CS598 / MPI heat diffusionSolvers

Two solvers, one accuracy target

Each physical step solves the same A x = b, starting from x = b. Only the iterative method changes.

Jacobi

Repeatedly corrects each temperature estimate using the current residual. Each update is simple, but many may be needed.

  • Neighbor exchange every update
  • Convergence check after update 1, every 10 updates, and at the iteration cap

Conjugate gradient (CG)

Builds search directions that usually make more progress per update. Each update costs more because it needs additional calculations and global communication.

  • Neighbor exchange every update
  • Two global dot products per update
Residual: how well the computed x satisfies A x = b, relative to the size of b. Both methods must pass an independently recomputed residual ≤ 10⁻⁸.

We compare complete time to solution. A cheap iteration is useful only if the method does not need too many of them.

✛CS598 / MPI heat diffusionMeasurement

How the timings were collected

Two exclusive AMD EPYC 7713 nodes on the Illinois Campus Cluster, with ranks bound to physical cores.

One measured run

Discard a warm-up, reset the temperature field, then measure five physical steps. Runtime is the sum of each step’s slowest-rank time.

All ranks must finish. Each step’s compute and MPI breakdown comes from that same selected rank.

A fair reading of the results

We report the median of five trials. Whiskers show the observed min–max range, not confidence intervals.

Timing includes solver calculations, checks, and MPI calls. Field initialization, final accuracy verification, and output are excluded.

Placement matters: P = 1 uses one node. P ≥ 2 spreads the ranks evenly over both nodes. Five nearby trials share the same allocation.

All plotted runtime values are milliseconds for the entire five-step solve, rather than a single iteration or a single physical step.

Larger timesteps make each solve harder

At N = 1024 and P = 16, vary r = αΔt / h². Here α = 1 is diffusivity, Δt is timestep, and h is grid spacing.

r = 0.5 to 8 increases runtime

Jacobi: 30.7 to 317.6 ms. CG: 8.06 to 33.8 ms. Each measurement still covers five steps.

What changing r means

With the grid fixed, larger r advances farther in physical time per step and changes the system A x = b.

✛CS598 / MPI heat diffusionValidation

Correctness checks and interpretation limits

Every benchmark passed the same independently recomputed relative-residual tolerance of 10⁻⁸.

Why trust the computed solutions?

Tests match an independent serial solver and analytic sine solution. They also cover refinement, halos, physical boundaries, uneven partitions, and failure cases.

All 280 runs passed. The maximum residual was 9.985 × 10⁻⁹. Diagnostics checked timing selection and rejected a CG result with a misleading internal residual.

What the measurements cannot establish

MPI time includes waiting and imbalance. P = 1 uses one node while larger P uses two, so topology and rank count change together.

Trials share one allocation; they do not capture day-to-day variation. Fixed r changes the physical timestep with N. Results depend on this initial field, tolerance, hardware, and implementation.

Residual tolerance checks the linear solve. It does not by itself guarantee that different grids and timesteps have the same physical accuracy.

✛CS598 / MPI heat diffusionConclusions

What the study establishes

Two solvers, the same implicit heat model, and 280 validated measurements on a two-node allocation.

01

CG lowers time to solution

It wins every tested strong-scaling comparison because far fewer updates offset its higher cost per update.

02

Grid size changes useful parallelism

The 512 × 512 grid is fastest at 32 sampled ranks. The 1024 × 1024 grid still improves at 64.

03

Read runtime and MPI share together

MPI can exceed half the measured time while additional ranks still reduce total runtime.

Evidence and reproduction

The repository contains the solver, automated tests, Slurm scripts, raw JSON records, and analysis.

Build with CMake and OpenMPI. Run MPI work in an allocated compute-node job.
